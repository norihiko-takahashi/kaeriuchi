# U4・U5 コードの作成：まとめ

偽物の AI で、「手で入れる → ミスモン → かえりうち問題 → 撃破」が端から端まで動くところまで作りました。

## 1. 作ったもの

| 場所 | 内容 |
|---|---|
| `server/problems/pipeline.ts` | 生成 → 形の確認 → 安全のチェック → 検証 → 1問ずつ返す。足りなければ足りない役割だけ1回作り直す。時間切れ（30秒）なら、そこまでの問題で終える。検証していない問題は返さない（BR-45-2・3） |
| `server/problems/verify/arith.ts` | 検算の計算器。「式 = ?」の形の問題文だけを読み、分数を BigInt で正確に計算する。`eval` は使わない（U45-Q-3） |
| `server/problems/safety/` | 出さない言葉の一覧（ふつうの言葉を弾かないものだけ）と、個人情報らしい文字（電話番号、メール、郵便番号、番地までの住所）（U45-SAFE-1・2） |
| `server/ai/prompts` | `classify@1`（手で入れた間違いの判定）、`generate@2`（1回で1問。答えの形の条件）、`solve@2`（検証役。子ども向けとして適切かも答える） |
| `server/ai/providers/*` | `classifyMistake` を足した。Bedrock は、役割ごとに1問ずつ同時に呼び、1問目は1問目の呼び出しが終わればすぐ返す（U45-PERF-1） |
| `app/api/ai/classify` | 手で入れた間違いの判定（1日30回まで・10秒）。一覧にないタイプは `other` |
| `app/api/ai/generate` | 上の流れを NDJSON で返す。生成と検証の使用量と費用を、別々に記録する |
| `domain/math/rational.ts` | 分数（有理数） |
| `domain/battle/grading/` | 端末での採点。数値（値が同じなら正解。約分・小数・帯分数の条件）、選択式、短い文（似ていれば「unsure」）、並べ替え、自己採点（BR-45-7） |
| `domain/battle/state.ts` | バトルの規則（3回まで、ヒント2段階、ダメージ 100・70・40、「おなじ」は 40、「あってるのに ×」は1回のバトルで1問まで 100、撃破・あと一歩）（BR-45-4〜6・8） |
| `client/store/db.ts`、`battle-repo.ts` | IndexedDB のスキーマ v2（ミスモン、バトル、あとで採点し直す答え）。報告は送信待ち（outbox）に入れる。子どもの削除・全部の削除・書き出しにも入れた |
| `client/ai/api.ts`、`regrade.ts` | AI の API を呼ぶ。問題を1問ずつ受け取る。通信が戻ったら「おなじ？」の答えを AI で採点し直して記録する |
| `app/mistakes/new`（S-20）、`app/mistakes/found`（S-21）、`app/battle`（S-22・S-23）、`app/parent/reports` | 画面。ホームに「てで いれる」と、まだ倒していないミスモンの一覧を足した |
| `components/battle/` | 仮のミスモン（SVG）、HP のバー、答え方ごとの入力、「あれ？おかしいかも」 |
| `evals/run.mts` | 生成の評価を、本番と同じ流れで動かす（通った数、落とした理由、1問目までの時間、費用、人が確かめるための問題の一覧） |

## 2. 確かめたこと（ローカル・Node.js 26）

| 確認 | 結果 |
|---|---|
| 単体テスト | 289件すべて成功。`domain/`・`server/ai/`・`server/problems/` のカバレッジは行 98.9%・分岐 96.8% |
| E2E（Chromium） | 10件成功。U4・U5 の2件：撃破までの流れ（「あってるのに ×」の救済が1問までであること、約分していない答えも正解、報告が保護者メニューに出て、ニックネームが入らないこと）と、途中でやめて再開・3回間違えて「あと一歩」。どちらも axe と CSP の違反なし |
| 大きさの予算 | 新しい子ども向けの画面は 176〜182KB（予算 200KB） |
| 評価（偽物の AI） | 生成 1件合格（仕組みの確認） |
| WebKit の E2E | CI で確かめる |

## 3. 設計から変えたところ

| 設計 | 実際 | 理由 |
|---|---|---|
| 問題は `problems` の表に置く（nfr-design §5） | バトルの記録の中に入れた | 問題はバトルごとに作り、そのバトルでしか使わないため。表が1つ減り、保存が1回で済む |
| HP は `hp.ts`（nfr-design §1） | `state.ts` にまとめた | 状態と一緒に計算するため |
| 検算した問題は AI を呼ばない（機能設計 §4） | 検算した問題でも、検証役に「適切か」を聞く | ヒントと解説の文は計算では確かめられないため（U45-SAFE-1）。1問につき1回の呼び出しが増える |
| 画面に渡す ID | URL の `#` のあとに入れる（`/battle#<id>`） | オフラインでも、キャッシュした同じページとして開けるため |

## 4. まだできていないこと

| 項目 | 扱い |
|---|---|
| AI が作った問題の文に、習っていない漢字のふりがなを付ける（U45-UX-3） | 未対応。いまはプロンプトで「漢字は学年に合わせる」としているだけ。U6 までに入れる（2026-11-09 に決定、Issue #14） |
| 偽物の AI は、どの教科でも算数の問題を返す | 流れを確かめるためのもの。教科ごとの見本は、評価用データと一緒に作る |
| 間違いのタイプの本格的な一覧（seed.json は仮の9件） | `content-data-plan.md` の計画どおり作る |
| 本物の Bedrock での評価 | AWS の準備ができたら、`pnpm eval --provider bedrock --suite generate` で、1問目までの時間・費用・誤りの率を測る |
| ミスモンの絵と名前 | 仮のもの（OQ6）。U6 で図鑑の種族として作り直す |
| XP・図鑑・再来の日程 | U6 |
