# U4・U5 NFR 設計：問題の生成と検証、バトル

NFR 要件（`../nfr-requirements/nfr-requirements.md`）を、どう作るかに落とします。新しい外部のライブラリは入れません。

## 1. ディレクトリ

```
domain/battle/            # バトルの規則（純粋な関数。React と通信に依存しない）
├─ hp.ts                  # HP とダメージ（BR-45-5）
├─ state.ts               # 何問目・何回目・ヒント・結果を進める状態機械（BR-45-4・6）
└─ grading/               # 端末での採点（BR-45-7）
   ├─ normalize.ts        # 全角・半角、ひらがな・カタカナ、空白
   ├─ numeric.ts          # 分数・小数・帯分数、条件（約分して など）
   └─ index.ts            # 答え方ごとの振り分け
server/problems/          # 生成と検証（U4）
├─ pipeline.ts            # 生成 → 検証 → 安全 → 作り直し（BR-45-2）
├─ verify/arith.ts        # 検算用の小さな計算器（U45-Q-3）
├─ verify/solve.ts        # 検証役の AI で解いて比べる
└─ safety/                # 出さない言葉の一覧と、個人情報らしい文字（U45-SAFE-1・2）
app/api/ai/classify/route.ts
app/(child)/battle/...    # S-20〜S-23
client/battle/            # 画面とデータ（Dexie）をつなぐ
```

## 2. 生成と検証の流れ（`server/problems/pipeline.ts`）

1. プロバイダーが1問できるたびに、その問題をすぐ検証する（全部できるのを待たない）。
2. 検証の方法を、問題の形で選ぶ。
   - 数値で、問題文が決まった形の式（四則、分数、小数、かっこ）に読めるとき：計算器で解いて比べる。
   - それ以外：検証役の AI（`solve`）に、作った答えを見せずに解かせ、採点の規則（BR-45-7）で比べる。選択式は、選んだものが作った答えと同じかで比べる。
3. 検証役は、解いた答えと一緒に「子ども向けとして適切か」（`appropriate: boolean`）も返す。`SolveResult` に足す（U45-SAFE-1）。
4. 通った問題に `verification`（方法、作り直しの回数、プロンプトの版、プロバイダー、モデル）を付けて、NDJSON の1行として送る。
5. 全部できても足りなければ、1回だけ作り直す（足りない数だけ、前の問題を `avoid` に入れて）。
6. 30秒を超えたら打ち切る（U45-PERF-4）。最後の行で、通った数と「たりない」を知らせる。2問未満なら端末は「うまく つくれなかったよ」を出す。

## 3. 検算の計算器（U45-Q-3）

- 字句を読んで、数字・`+ - × ÷ * / ( )`・分数だけを受け付ける。それ以外の文字があれば「計算器では確かめられない」として、検証役の AI に回す。
- 分数は分子・分母の整数（`BigInt`）で計算し、小数の誤差を出さない。
- `eval`・`Function` は使わない。Biome のルールでも禁止する。

## 4. 端末での採点（BR-45-7・U45-OFF-2）

| 答え方 | 端末でのやり方 |
|---|---|
| 数値 | 分数（整数の組）にそろえて比べる。問題の `format.condition`（`reduced`・`decimal`・`mixed` など）があれば、その形かも確かめる |
| 選択式・並べ替え | そのまま比べる |
| 短い文 | 一覧と比べる。似ているとき（正規化した文字の距離が近い、または一覧の答えを含む）だけ、通信できれば `/api/ai/grade`、通信できなければ「おなじ？」（ダメージ 40）。あとで AI に採点し直してもらう分は、送信待ち（outbox）に入れる |
| 自己採点 | お手本を見せて「できた／もう一回」 |

`AnswerFormat` の数値に `condition` を足します（`ProblemDraft` のスキーマの変更。プロンプトの版を上げる）。

## 5. 端末に残すもの（Dexie のスキーマ v2）

| 表 | 中身 |
|---|---|
| `mistakes` | ミスモン：教科、問題文、きみの答え、正しい答え、間違いのタイプ、状態（未撃破・撃破・あと一歩） |
| `problems` | かえりうち問題：問題、答え、ヒント、解説、`verification` |
| `battles` | バトル：ミスモン、問題の順番、いまの位置、各問題の回数とヒントとダメージ、「あってるのに ×」を使ったか、結果 |
| `outbox`（既存） | 報告、あとで AI に採点し直してもらう答え |

- v1 から v2 への移行の処理と、その単体テストを書く（U1 の決まり）。
- 1回答えるごとに `battles` を書く（U45-OFF-3）。

## 6. 回数の上限

- `DAILY_LIMITS` に `classify: 30` を足す（U45-COST-1）。
- 1日に登録できる間違いの数（10問）は、端末で `mistakes` の作った日付で数える。

## 7. テスト

- `domain/battle/**` と `server/problems/**` を、カバレッジの対象（90%）に足す。
- 計算器と採点は、表のテスト（入力と期待する結果の一覧）で網羅する。
- 生成の流れは、Mock のプロバイダーに「検証に落ちる問題」「不適切な言葉の入った問題」を返させて、出さないことを確かめる。
- E2E：手で入れる → ミスモン → 3問 → 撃破、と、途中でやめて再開、と、「あってるのに ×」の救済が1問までであること。
