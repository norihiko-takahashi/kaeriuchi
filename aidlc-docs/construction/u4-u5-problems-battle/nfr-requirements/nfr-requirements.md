# U4・U5 NFR 要件：問題の生成と検証、バトル

U2 の NFR（`../../u2-ai-foundation/nfr-requirements/nfr-requirements.md`）はそのまま引き継ぎます。ここには、U4・U5 で新しく決めることだけを書きます。
★ は 2026-11-09 にチャットで1つずつ決めたものです。

## 1. 性能

| # | 要件 |
|---|---|
| U45-PERF-1 | 1問目が端末に届くまで p90 で 10秒以内（NFR-S2）。検証が済んだ問題から1問ずつ送る |
| U45-PERF-2 | 端末での採点は 100ms 以内（NFR-S3） |
| U45-PERF-3 | 間違いのタイプの判定（`/api/ai/classify`）は p90 で 5秒以内。時間切れは 10秒 |
| U45-PERF-4 | 生成から検証まで、全部で 30秒を超えたら打ち切る（そこまでに通った問題の数で BR-45-2 を当てはめる） |

## 2. 問題の正しさ

| # | 要件 |
|---|---|
| U45-Q-1 | 検証していない問題は、端末に送らない。サーバーで止める（BR-45-2）。端末でも `verification` がない問題は出さない（二重の守り） |
| U45-Q-2 | ★ 検証役のモデルは、**まず作る側と同じモデル**で始める。評価のコマンドで、検証をすり抜けた誤りの率をモデルの組み合わせごとに測り、その結果で変えるかを決める。モデルは役割ごとに設定で変えられる（`BEDROCK_MODEL_VERIFY`） |
| U45-Q-3 | 算数・数学の検算は、決まった形の数式だけを計算する小さな計算器で行う（`eval` などで文字列をコードとして実行しない） |
| U45-Q-4 | 検証の結果（方法、作り直しの回数、プロンプトの版、プロバイダー、モデル）を問題ごとに残す |
| U45-Q-5 | 評価のコマンド（`pnpm eval --suite generate`）で、検証をすり抜けた誤りの率を測れるようにする（NFR-Q1a） |

## 3. 安全

| # | 要件 |
|---|---|
| U45-SAFE-1 | ★ 不適切な内容のチェックは2段にする。(1) 出さない言葉の一覧（リポジトリで管理）で弾く。(2) 検証役の AI が、解くのと同じ呼び出しで「子ども向けとして適切か」も答える（呼び出しは増やさない）。AI のプロバイダーを変えても同じように効く。Bedrock Guardrails は使わない（日本語での精度が未確認、費用と時間が増える、Bedrock 以外で使えない）。一覧の漏れは、報告と評価で補う |
| U45-SAFE-2 | 作った問題に、個人情報らしい文字（電話番号、メールアドレス、住所らしい文字）があれば出さない |
| U45-SAFE-3 | 子どもが入れた文（問題文・答え）は「データ」として扱い、AI に指示として実行させない（U2-SEC-4 と同じ） |

## 4. プライバシー

| # | 要件 |
|---|---|
| U45-PRIV-1 | 手で入れた問題文と答えは、サーバーに保存しない。ログにも出さない（U2-PRIV-2 と同じ） |
| U45-PRIV-2 | 報告には、画像とニックネームを含めない（BR-45-8）。子どものプロフィールの ID も入れない（U8 で送るときは、保護者の単位で数えるだけにする） |
| U45-PRIV-3 | 端末に残すのは、ミスモン・問題・バトルの記録・報告の文字だけ（`data-inventory.md` の範囲） |

## 5. オフラインと再開

| # | 要件 |
|---|---|
| U45-OFF-1 | 問題を受け取ったあとは、通信が切れてもバトルを最後まで続けられる |
| U45-OFF-2 | ★ 通信が切れていて、短い文の答えが一覧にはないが似ているときは、**子どもに正解を見せて「おなじ？」と聞く**（自己採点と同じ形）。「おなじ」なら正解として扱い、ダメージは 40（答えを見てから選べるため）。通信が戻ったら AI で採点し直し、結果を記録して評価に使う（子どもの結果はさかのぼって変えない） |
| U45-OFF-3 | バトルの途中の状態（何問目か、何回目か、ヒント、ダメージ）は、1回答えるごとに端末に保存する。アプリを閉じても続きから再開できる |

## 6. 費用と回数

| # | 要件 |
|---|---|
| U45-COST-1 | ★ 間違いのタイプの判定（`/api/ai/classify`）は、端末ごとに **1日30回まで**（解析と同じ）。U8 で保護者ごとに数える形に変える |
| U45-COST-2 | 1回の戦い（生成＋検証＋作り直し）にかかる費用の目安を、評価のコマンドで出す（NFR-C2） |
| U45-COST-3 | 1日に登録できる間違いの数（BR-3.1、初期値10問）は、端末で数える（U8 でサーバーでも数える） |

## 7. 使いやすさ

| # | 要件 |
|---|---|
| U45-UX-1 | 問題を待っている間は、ミスモンが現れる演出を見せる。「視差効果を減らす」設定では動きを止める（NFR-U4） |
| U45-UX-2 | バトルの画面は WCAG 2.2 AA。HP の変化は、色だけでなく数字と読み上げでも伝える |
| U45-UX-3 | 低学年の表示では、問題・ヒント・解説に、習っていない漢字のふりがなを付ける（U1 の仕組み） |
