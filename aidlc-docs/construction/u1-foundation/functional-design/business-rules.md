# U1 機能設計：ビジネスルール

## BR-1 プロフィール

| # | ルール |
|---|---|
| BR-1.1 | 1人の保護者が作れるプロフィールは、最大4人まで |
| BR-1.2 | ニックネームは1〜12文字。前後の空白は取り除く。改行は使えない。同じ保護者の中で同じニックネームは使えない |
| BR-1.3 | ニックネームが本名らしいとき（例：漢字だけで2〜6文字、「さん」「くん」が付いている、など）は、やさしく確認する。「このままにする」を選べば保存できる（入力は止めない）。判定の方法は課題 R1 と一緒に見直す |
| BR-1.4 | ニックネームに URL、メールアドレス、電話番号の形が入っていたら、保存できない |
| BR-1.5 | 学年は、毎年4月1日（日本時間）に自動で1つ上がる。MVP では、中3の次は「卒業」として表示し、プロフィールはそのまま使える（学年は中3のまま）。**Phase 2 で高校生（高1〜高3）に対応**したら、中3の次は高1に上がる。学年の型は、高校の学年を足せる形にしておく |
| BR-1.6 | 学年が変わったときは、表示モードも学年に合わせて変わる。ただし、保護者が手で表示モードを変えていた場合は、そのままにする |
| BR-1.7 | アバターは、プリセットの部品（顔・色・アクセサリー）の組み合わせだけ |

## BR-2 PIN と保護者メニュー

| # | ルール |
|---|---|
| BR-2.1 | 保護者の PIN は**6桁**の数字。同意の直後に必ず設定する。簡単すぎるもの（「000000」のような同じ数字の繰り返し、「123456」「987654」のような連番）は使えない |
| BR-2.2 | PIN は、ソルトを付けてハッシュにして保存する（PBKDF2 などの、時間のかかる方式） |
| BR-2.3 | PIN を5回続けて間違えたら、1分間入力できない。その後も間違えるたびに、待つ時間を倍にする（最大30分） |
| BR-2.4 | 端末の認証（指紋・顔など）を登録すれば、PIN の代わりに使える |
| BR-2.5 | 保護者メニューは、何も操作しないまま5分たつと、自動で閉じる |
| BR-2.6 | PIN を忘れたときは、保護者がログインし直せば、PIN を設定し直せる（U8 でマジックリンクにつなぐ） |
| BR-2.7 | 子どものプロフィールの PIN は任意（4桁。子どもが覚えやすいように、保護者の PIN より短くする）。保護者メニューから、設定・解除できる |

## BR-3 使い方のルール

| # | ルール |
|---|---|
| BR-3.1 | 1日に登録できる間違いの数：初期値は10問。1〜30問の範囲で変えられる。子どもごとに設定する |
| BR-3.2 | 使える時間帯：初期値は「制限なし」。開始と終了の時刻を設定できる。時間外は、子どもの画面に「きょうは おしまい。また あしたね」と出す |
| BR-3.3 | 「1日」の区切りは、端末の時刻で**午前0時**にする。連続記録、1日に登録できる数の上限、「今日の再来ミスモン」の計算に使う。0時をまたいだバトルは、**始めた日の分**に数える |
| BR-3.4 | 通知は、初期値はオフ |

## BR-4 データの書き出し・削除

| # | ルール |
|---|---|
| BR-4.1 | 書き出しは JSON の形式。子どもごと、または全部を選べる。画像は含めない |
| BR-4.2 | 削除するときは、ニックネームを入力して確認する |
| BR-4.3 | 削除すると、端末の中のデータはすぐに消す。クラウドのデータは、U8 で `purge` につなぐ（論理削除のあと、30日以内に本当に消す） |

## BR-5 同意

| # | ルール |
|---|---|
| BR-5.1 | 同意事項には版の番号を付ける。版が上がったら、次に保護者メニューを開いたときに、もう一度同意してもらう |
| BR-5.2 | 同意した版と日時を記録する |
| BR-5.3 | 同意事項の内容（文章）は、Construction の中で、法務やプライバシーの担当の確認を受けてから確定する |
