## 3. 設計から変えたこと

| # | 設計 | 実装 | 理由 |
|---|---|---|---|
| 1 | CSP のスクリプトは nonce で守る（`nfr-design.md` §4） | **設計どおり nonce にした**（`proxy.ts`、`server/security/csp.ts`）。そのため、すべての画面をリクエストのたびに描画する。オフライン用の画面は、Service Worker を入れたときにサーバーから取得してキャッシュする | 一度は `'unsafe-inline'` で作ったが、リスクを受け入れるかを議論して、nonce に戻した（下の §6）。SRI（試験的な機能）は、Next.js がページに直接埋め込むスクリプトに効かないため使えなかった |
| 2 | 本番かどうかを `NODE_ENV` で見る | `APP_ENV` を足した | ビルドではいつも `NODE_ENV=production` になるので、CI やプレビューと本番を区別できないため |
| 3 | — | オフラインのときは、画面の移動を「キャッシュしたページを直接開く」方式に切り替える（`client/pwa/navigate.ts`） | Next.js の画面の移動は、オフラインだとネットワークから画面のデータを取ろうとして止まるため |
| 4 | 端末の認証（指紋・顔など）で保護者メニューに入れる（BR-2.4） | U8 に回した | パスキー（WebAuthn）と一緒に作る方が、作り直しが少ないため |
| 5 | Node.js は LTS 版 | Node.js 22（`.nvmrc`） | この開発環境に入っている版に合わせた。22 のサポートは 2027年4月までなので、U8 で公開先を決めるときに 24 に上げる |

## 4. 残っていること・注意点

- **同意事項の文章は仮のもの**（版 `0.1.0-draft`）。本番で使う前に、法務・プライバシーの確認が必要です。
- **ログインは開発用**（メールアドレスを入れるだけ）。U8 でマジックリンクとパスキーに置き換えます。
- **絵（アバター・名前の説明の3コマ・アイコン）は仮の SVG**（OQ6）。
- **依存ライブラリの moderate の脆弱性が2件**：`glob` と `minimatch`。どちらも Serwist がビルドのときだけ使うもので、アプリの実行には含まれません。修正版は大きな版の更新になるため、Serwist の更新を待ちます。
- `zod` の high の脆弱性は、`pnpm-workspace.yaml` の `overrides` で修正版にそろえています。Serwist が上げたら外します。

## 6. CSP についての判断（2026-11-08）

### 経緯
1. 最初の実装では、`script-src 'self' 'unsafe-inline'` にした。画面を静的に作り、ビルドのときに前もってキャッシュするため。
2. レビューで「リスクを受け入れる理由」を議論した。`'unsafe-inline'` を受け入れる主な理由は開発の都合で、セキュリティの理由ではなかった。子どものデータを扱うこと、「後で強める」は忘れられやすいこと、nonce にしても手間が大きくないことから、**受け入れないことにした**。
3. まず SRI（Next.js の試験的な機能）を試した。外部のファイルにはハッシュが付くが、Next.js がページに直接埋め込むスクリプト（3つ）には効かず、厳しい CSP では画面が動かなかった。
4. nonce にした。

### いまの設定
- `script-src 'self' 'nonce-<リクエストごと>' 'strict-dynamic'`：ページに紛れ込んだスクリプトは動かない。HTML に紛れ込んだイベントのスクリプト（`onerror` など）が止まることを、E2E（`e2e/security.spec.ts`）で確かめている。
- 外部のドメインは1つも許可しない（`connect-src 'self'` など）。
- `style-src 'self' 'unsafe-inline'`：スタイルは許可している。CSS の注入でできることは、スクリプトの注入よりずっと少ないため。

### 残っている弱いところ（受け入れたもの）
| 弱いところ | 理由・対策 |
|---|---|
| オフラインで開いたときは、キャッシュしたときの nonce を使い回す | 本来 nonce は1回限りだが、キャッシュした HTML の中身は変わらないので、攻撃者がその nonce を知って使うには、別の方法でスクリプトを入れる必要がある。オンラインのときは毎回変わる |
| ページの移動による持ち出し（`location = 攻撃者のURL?データ`）は、どの CSP でも止められない | スクリプトの注入そのものを止めるので、ここに至らない |
| 依存ライブラリの乗っ取りは、CSP では防げない | 依存ライブラリの固定、脆弱性のスキャン、Dependabot の更新のレビューで対応する |
| ブラウザの拡張機能は、CSP の外で動く | 防げない。保護者向けの説明に入れる |

### CSP とは別に入れる守り（U4・U8）
- HTML をそのまま埋め込む書き方（`dangerouslySetInnerHTML`）を lint で禁止する
- AI の出力は、JSON スキーマで検査したうえで、必ず「文字」として表示する
- 数式の表示（KaTeX）は、信頼しない設定（`trust: false`）で使う
- Cookie は `HttpOnly`・`SameSite` にし、取り返しのつかない操作にはログインのし直しを求める
