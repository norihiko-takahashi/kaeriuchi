# U1 NFR 要件：基盤・プロフィール

Inception の非機能要件（`inception/requirements/requirements.md` §5）のうち、U1 に関わるものを、測れる形に具体化します。

## 1. PWA・オフライン

| # | 要件 | 確かめ方 |
|---|---|---|
| U1-PWA-1 | ホーム画面に追加できる（Web App Manifest、各サイズのアイコン、`display: standalone`） | Lighthouse の PWA のチェック、実機での確認 |
| U1-PWA-2 | 一度開いたあとは、オフラインでも、アプリが開き、プロフィールを選んで、ホームまで進める | Playwright でネットワークを切って確認 |
| U1-PWA-3 | 新しいバージョンを公開したとき、**子どもが使っている途中では切り替えない**。次に起動したとき、または保護者メニューを開いたときに切り替える | E2E |
| U1-PWA-4 | ブラウザに「保存したデータを消さないで」とお願いする（`navigator.storage.persist()`）。許可されたかどうかを、保護者メニューに表示する | 単体テスト、実機での確認 |

### iOS Safari の注意点
- ホーム画面に追加していないサイトの場合、Safari は**7日間使わないと、そのサイトが保存したデータを消す**ことがあります。
- クラウドに同期する（U8）ので、データが完全になくなることはありません。ただし、オフラインの間に記録した、まだ送っていない変更は消える可能性があります。
- そのため、初めて使うときの流れの最後で、ホーム画面に追加するよう、手順の画像つきで案内します。

## 2. 性能

| # | 要件 | 条件 |
|---|---|---|
| U1-PERF-1 | 最初の表示（LCP）は 2.5秒以内 | 中くらいの性能の Android 端末、4G 回線の想定（Lighthouse のモバイル設定） |
| U1-PERF-2 | 子ども向けの画面で最初に読み込む JavaScript は、圧縮して 200KB 以内 | ビルドのときに自動で測る |
| U1-PERF-3 | 2回目以降の起動（キャッシュあり）は、1秒以内にプロフィールを選ぶ画面が出る | 実機 |
| U1-PERF-4 | 画面の操作に対する反応（INP）は 200ms 以内 | Lighthouse、実機 |

## 3. アクセシビリティ

| # | 要件 |
|---|---|
| U1-A11Y-1 | WCAG 2.2 の AA に準拠する。CI で自動チェック（axe）をかけ、違反があれば失敗にする |
| U1-A11Y-2 | タッチする部分の大きさは、表示モードごとの最小値（56px / 48px / 44px）を守る |
| U1-A11Y-3 | ふりがなは HTML の `<ruby>` で付け、スクリーンリーダーが正しく読めるようにする |
| U1-A11Y-4 | OS の「視差効果を減らす」設定がオンなら、アニメーションを止めるか、控えめにする |
| U1-A11Y-5 | OS の文字の大きさの設定に合わせて、画面が崩れない（200% まで） |

## 4. セキュリティ・プライバシー

| # | 要件 |
|---|---|
| U1-SEC-1 | 通信は HTTPS だけ（HSTS を付ける） |
| U1-SEC-2 | Content Security Policy を厳しく設定し、**外部のスクリプトを読み込まない**（子ども向けの画面に外部の分析ツールや広告を入れない、という NFR-P9 を、仕組みでも守る） |
| U1-SEC-3 | カメラなどの権限は、自分のサイトからだけ使えるように制限する（Permissions-Policy） |
| U1-SEC-4 | PIN は、ソルトを付けて、時間のかかる方式（PBKDF2、ブラウザの WebCrypto）でハッシュにして保存する |
| U1-SEC-5 | 秘密情報（API キーなど）を、ブラウザに渡すコードに入れない。CI で秘密情報のスキャンをかける |
| U1-SEC-6 | 依存ライブラリの脆弱性を、CI で毎回チェックし、重大なものがあれば失敗にする |

### PIN の位置づけ（大事な前提）
- 保護者の PIN は、**子どもが保護者メニューに入らないようにする「子どもよけ」**です。データを守るための鍵ではありません。
- 6桁の PIN は100万通りしかないので、ハッシュが漏れれば、コンピューターで総当たりにすれば、すぐに見つかってしまいます。
- そのため、取り返しのつかない操作（アカウントの削除、クラウドのデータの書き出し・削除）には、PIN に加えて、**保護者のログインのし直し**（パスキー、またはマジックリンク）を求めます。これは U8 で作ります。

## 5. 移しやすさ（どこでも動かせること）

| # | 要件 |
|---|---|
| U1-PORT-1 | Next.js は `output: "standalone"` でビルドし、Node.js だけで動く |
| U1-PORT-2 | 特定のクラウドだけの機能（Vercel の KV や Edge Config、AWS だけの SDK など）を、`server/*/providers` と `server/*/stores` の外では使わない |
| U1-PORT-3 | 設定は環境変数だけで行う。起動するときに、Zod で中身をチェックし、足りなければ起動しない |
| U1-PORT-4 | Docker のイメージ1つで動く。`docker compose up` で、ローカルで全部が動く |

## 6. 品質（テスト）

| # | 要件 |
|---|---|
| U1-TEST-1 | ビジネスルール（BR-1〜BR-5）は、すべて単体テストで確かめる |
| U1-TEST-2 | データ構造の移行は、すべて単体テストで確かめる |
| U1-TEST-3 | 初めて使うときの流れ（ログイン → 同意 → PIN → プロフィール作成 → ホーム）を、E2E テストで確かめる。Chromium と WebKit（iOS Safari に近いもの）の両方で動かす |
| U1-TEST-4 | `domain/` のテストのカバレッジは 90% 以上 |

## 7. 対応環境

Inception の NFR-E1 のとおり、iOS Safari 17 以上、Android Chrome の最新2バージョン、iPadOS を対象にします。
