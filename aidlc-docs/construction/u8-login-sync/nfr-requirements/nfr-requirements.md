# U8 NFR 要件：ログイン・クラウド同期

U1〜U7 の NFR はそのまま引き継ぎます。ここには、U8 で新しく決めることだけを書きます。

| # | 要件 |
|---|---|
| U8-SEC-1 | ログイン用のリンク・端末をつなぐ番号・セッションの値は、推測できない乱数（32バイト以上。番号は8けた）で作り、データベースには**ハッシュだけ**を保存する（漏れても使えない） |
| U8-SEC-2 | セッションの Cookie は HttpOnly・Secure・SameSite=Lax・`__Host-` 付き。30日（使うたびに延びる）。ログアウト・端末のログアウト・アカウントの削除で、サーバー側でも無効にする |
| U8-SEC-3 | 状態を変える API（同期・アカウント）は、同じ出どころ（Origin の確認）からだけ受ける |
| U8-SEC-4 | すべての同期・アカウントの処理は、ログインした保護者の ID で絞る。データベースでも行ごとのアクセス制御（RLS）をかけ、アプリのまちがいでほかの家庭の記録が見えないようにする |
| U8-SEC-5 | 送られた変更は Zod で形を確かめる。1件 64KB・1回 200件・1回 1MB まで。ほかの保護者の子ども・テストを指すもの、未来の日付は受け付けない |
| U8-SEC-6 | 回数の制限：リンクの送信は同じアドレスに1時間5回・同じ接続元から1時間20回。番号の入力は5回まちがえで無効。同期は1端末1分に30回まで |
| U8-PRIV-1 | メールアドレスはログ・送信待ち・エラーの記録に残さない（保護者の ID だけ）。メールの本文に、子どものニックネームや記録を入れない |
| U8-PRIV-2 | 削除の印を付けてから7日を過ぎた記録は、毎日1回の処理で本当に消す。消したことを、数だけ記録する（中身は残さない） |
| U8-PRIV-3 | データは東京リージョンだけに置く（バックアップも）。データベースは保存時に暗号化（KMS）、通信は TLS |
| U8-PERF-1 | 同期1回（送信 50件・受信 50件）は、サーバーで p90 300ms 以内 |
| U8-PERF-2 | 同期は画面の操作を止めない（裏で動く）。オフライン・失敗のときは、だんだん間隔をあけてやり直す（最大 5分） |
| U8-REL-1 | 同じ変更を2回送っても、結果は同じ（ID と版で判定する）。途中で切れても、記録が消えたり二重になったりしない |
| U8-REL-2 | データベースは毎日バックアップ（7日分保存）。β版は1台、利用者が増えたら2台（マルチ AZ）にする |
| U8-COST-1 | β版のうちの AWS の費用の目安：月 1万円前後（Fargate 2台・ALB・RDS 1台・SES。出口は公開サブネット）。本番は VPC エンドポイントの分（約9,000円）が増える。費用の通知を月 1.5万円で出す |
| U8-TEST-1 | まとめ方のルール・ログインのトークン・削除の期限は、純粋な関数にして単体テスト（カバレッジ 90%）。同期の API は、メモリと Postgres の両方の保存先で同じテストを通す |
| U8-TEST-2 | E2E：開発用のログインで、メールのリンク → 同意 → プロフィール → 2つ目の端末を番号でつなぐ → 片方でバトル → もう片方で記録が見える。オフラインでバトル → つながったら届く |
