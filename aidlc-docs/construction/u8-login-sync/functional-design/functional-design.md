# U8 機能設計：ログイン・クラウド同期

2026-11-14 にユーザーと決めた点：

| # | 点 | 決定 |
|---|---|---|
| 1 | 本番の置き場所（OQ7） | **AWS の東京リージョンにまとめる**（アプリ・Postgres・メール送信）。**ログインは自分たちで作る**（メールのリンクとパスキー。定番の部品を使い、ほかのクラウドにも移せる形） |
| 2 | 削除したデータ | **7日は取り消せ、そのあと本当に消す**。押した瞬間から、画面にも同期にも出ない |
| 3 | 子ども用の端末をつなぐ方法 | **保護者のスマホで番号を出して入れる**（8けた・10分・1回きり） |

前から決まっていること：パスワードは使わない（FR-1.0）、子どもはログインしない（FR-1.3）、端末の一覧とほかの端末のログアウト（FR-1.6）、記録の種類ごとのまとめ方（domain-model.md）、使った時刻は同期せず日付だけ（NFR-P11）、画像は同期しない（FR-9.3）、開発用の仕組みで全部動く（NFR-I2）。

## 1. ログイン（US-1.1・1.4）

```
はじめて：ログイン（メール）→ メールのリンクを開く → 同意 → 保護者の PIN → プロフィール（いまの流れ）
2回目から：ログイン → 「パスキーで ログイン」（指紋・顔）または メールのリンク
```

- **メールのリンク**：メールアドレスを入れると、ログイン用のリンクを送る。リンクは **15分・1回きり**。同じアドレスへの送信は 1時間に 5回まで。アドレスがまだ登録されていなければ、そのリンクで新しいアカウントを作る（「登録されていません」とは言わない。どのアドレスが使われているか分からないように）
- **パスキー**：ログインしたあと、保護者メニューから登録できる（任意）。登録すると、次からは「パスキーで ログイン」だけで入れる
- **ログインの続く期間**：その端末で **30日**。使うたびに延びる。保護者向けの画面に入るときは、これまでどおり PIN か端末の認証を求める（US-7.2）
- **リンクを別の端末で開いたとき**：開いた端末がログインする（リンクを頼んだ端末ではない）。画面に「この たんまつで ログインしました」と出す
- 開発用（`AUTH_PROVIDER=dev`）では、メールを送らずに、リンクをサーバーのログと画面に出す

## 2. 端末をつなぐ（決定 3）

- 保護者メニュー →「たんまつを つなぐ」で、**8けたの番号**を出す（10分で使えなくなる・1回きり・同時に出せるのは1つ）
- 子どもの端末のログインの画面で「ばんごうで つなぐ」→ 番号を入れる → その端末がアカウントにつながる
- 番号を5回間違えると、その番号は使えなくなる
- つないだ端末は「端末の一覧」に出る（名前は「iPad（Safari）」のように、ブラウザの情報から付け、保護者が変えられる）

## 3. 端末の一覧（US-1.6、FR-1.6）

- 保護者メニュー →「ログインしている たんまつ」：端末の名前、つないだ日、最後に同期した日（時刻は出さない）
- 「この たんまつを ログアウト」で、ほかの端末をログアウトさせられる。その端末は次に同期しようとしたときにログインの画面に戻る。**端末の中の記録は消さない**（送っていない変更が残っているかもしれないため。保護者が「この たんまつの データを けす」を押せば消える・U1 のまま）

## 4. 同期（US-1.5、FR-9）

- **いつ**：起動したとき、画面が前に戻ったとき、変更のあと 5秒たったとき、オンラインに戻ったとき。オフラインのときはしない（記録は端末の「送信待ち」にたまる・U1 のまま）
- **何を**：送信待ちの変更を送り（push）、前回より後のクラウドの変更を受け取る（pull）。まとめて送るのは 1回 200件まで
- **まとめ方**（domain-model.md のとおり）：
  | 記録 | まとめ方 |
  |---|---|
  | バトル・報告・採点し直し | 足すだけ（同じ ID は1回だけ） |
  | 子どものプロフィール・ミスモン・テスト | 新しい版を採用（`version` が大きいほう。同じならサーバーに先に届いたほう） |
  | 保護者の設定（使い方のルールなど） | 最後に変えたほうを採用（更新の時刻で比べる。学習の記録ではないので時刻を使う） |
  | 削除 | 削除が勝つ（消したものは戻らない） |
  | XP・図鑑・連続記録・再来の日程 | 同期しない（バトルの記録から計算し直す・U6-DATA-1） |
- **同期しないもの**：子どもの PIN と保護者の PIN のハッシュ（端末ごと）、撮影の写真（そもそも保存しない）、端末の ID、時刻（日付だけ・NFR-P11）
- **はじめてログインした端末に記録があったとき**：その端末の記録を、ログインしたアカウントに入れる。すでに別の保護者のアカウントの記録がある端末で、違うアカウントにログインしたときは、「この たんまつには ほかの アカウントの きろくが あります」と出して、端末の記録を消すか、やめるかを選ぶ（混ぜない）
- **画面に出す状態**：保護者メニューに「さいごに どうきした ひ」と「おくっていない へんこう：◯件」。失敗が続いたら「どうき できていません」と出す（子どもの画面には出さない）

## 5. 削除（US-7.3、FR-8.4・8.5、決定 2）

- **子どものデータを削除**：その子のプロフィール・ミスモン・テスト・バトル・報告に削除の印を付ける。すぐにすべての端末の画面から消える（次の同期で）。**7日のうち**なら保護者メニューの「けしたデータ」から取り消せる。7日を過ぎたら、サーバーが本当に消す（バックアップからは、バックアップの保存期間のうちに消える）
- **アカウントを削除**：保護者と子ども全員の記録に削除の印を付け、すべての端末をログアウトさせる。7日のうちなら、同じメールでログインすると「取り消す」を選べる。過ぎたら本当に消す
- **書き出し**（US-7.3）：いまの端末からの書き出し（U1）に加えて、クラウドの記録も含めて書き出せる（JSON）

## 6. 安全

- すべての同期・アカウントの API は、ログインした保護者の記録だけを触る（サーバーの中でも、保護者の ID で必ず絞る）
- 送られた変更は Zod で形を確かめる。ほかの保護者・子どもの ID を指すもの、未来の日付、大きすぎるものは受け付けない
- ログインの Cookie は HttpOnly・Secure・SameSite=Lax。API は同じ出どころからの呼び出しだけを受ける（CSRF 対策）
- 1日の AI の回数の上限（30回）を、端末ごとから**子どもごと**に変える（2026-11-14 に決定。保護者が決める「1日に登録できる数」も子どもごとなので、そろえる）。AI の API には子どもの ID を付けて呼び、サーバーはその子がログインした保護者の子どもかを確かめてから数える。数はサーバーのデータベースで数える（いまはサーバーのメモリ）
- メールアドレスはログ・送信待ちに残さない。ログには保護者の ID だけ

## 7. レビューで確かめた点（2026-11-14、1つずつ確認して OK）
リンクは15分・1回きり・1時間に5回まで／登録されていないアドレスでも同じ表示で新しいアカウントを作る／ログインは30日（使うたびに延びる）／端末をつなぐ番号は10分・5回まちがえで無効／ログアウトさせた端末の記録は消さない／同期のタイミングと1回200件／まとめ方（バトルは足す・ほかは新しいほう・削除が勝つ）／PIN・写真・時刻は同期しない／別のアカウントの記録がある端末では混ぜない／同期の知らせは保護者メニューだけ／AI の回数は子どもごと

## 8. まだ決めないこと
- アプリを動かす AWS のサービス（App Runner か ECS か）と、データベースの種類（Aurora Serverless か RDS か）：インフラ設計で比べる
- メールの文面の細部：コードで作り、確認の画面でユーザーに見てもらう
