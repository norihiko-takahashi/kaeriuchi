# U8 インフラ設計：AWS の構成

2026-11-14 に決定：**ふつうの ECS（Fargate）**、構成は **AWS CDK（TypeScript）**、データベースは **RDS for PostgreSQL（1台から）**、メールは **Amazon SES**。すべて東京リージョン（ap-northeast-1）。

## 1. 構成

```
利用者 ─ HTTPS ─▶ ALB（公開サブネット、ACM の証明書。WAF は本番から）
                    └─▶ ECS Fargate（アプリ。β版は1台、Graviton・0.25 vCPU・1GB）
                           ├─▶ RDS for PostgreSQL（隔離サブネット、暗号化、バックアップ 7日）
                           └─▶ Bedrock・SES・ECR・CloudWatch Logs・Secrets Manager（出口は下の表）
毎日1回の処理（EventBridge → ECS のタスク）：削除から7日過ぎた記録を消す
```

構成図：https://claude.ai/artifact/GgzjiTnYAK2YYGNo2YEpHf

### アプリから AWS のサービスへの出口（2026-11-14 に決定）

| 環境 | 出口 | アプリの置き場所 | 月の費用（出口の分） | AWS の外へ出られるか |
|---|---|---|---|---|
| **β版** | **C. 公開サブネットに置く** | 公開サブネット（公開 IP あり。入ってくる通信は ALB からだけに、セキュリティグループで絞る） | 約1,000円 | 出られる |
| **本番** | **B. VPC エンドポイントだけ** | プライベートサブネット（公開 IP なし） | 約9,000円（約6つ） | 出られない |

- 比べた案：A. NAT ゲートウェイ1台（約7,000円、外へ出られる）。どの案でも、データベースは隔離サブネットで、外から直接アプリに届く道は ALB だけ。
- 最初の案（「NAT を置かないと安くなる」）は誤りだった。VPC エンドポイントは1つずつに費用がかかり、約6つ要るため NAT より高い。
- CDK では、環境ごとの設定1つ（`egress: "public" | "endpoints"`）で切り替える。
- ログは CloudWatch Logs（30日）。

### β版の大きさと費用（2026-11-15 に決定）

| | β版 | 本番（公開の前に見直す） |
|---|---|---|
| アプリ | Fargate **1台**（Graviton・0.25 vCPU・1GB）。入れ替えは新しい版が動いてから古い版を止めるので、止まらない。落ちたときは ECS が立て直す（1〜2分） | 2台（2つの AZ） |
| データベース | RDS for PostgreSQL db.t4g.micro・1台 | 2台（マルチ AZ）を検討 |
| WAF | **入れない** | 入れる |
| 出口 | 公開サブネット | VPC エンドポイント |
| 費用の通知（AWS Budgets） | **月 1万円** | 見直す |

- 月の目安：約7,000〜7,500円（AI の分は別）。東京の単価は、デプロイの前に AWS の料金の計算ツールで確かめる（この作業環境からは AWS の料金のページを直接開けないため、金額は見積もり）。
- AWS アカウントは、**すでにあるもの**を使う（新しいアカウント向けの無料のクレジットは使えない）。U2 で決めた「AI の呼び出しの記録は文章だけ」の設定が会社のアカウントの設定と合わないときは、そのときに相談する。
- さらに安くする方法として比べたもの：Fargate Spot（1台だと止められたときに開けない）、Savings Plans（1年の約束。利用者が増えてから）、Aurora Serverless v2 を止める設定（最初の接続が最大15秒待つ）、API Gateway の HTTP API（30秒の上限と、少しずつ送れないため問題作りが動かない）、Lightsail（AI を呼ぶ権限の渡し方が方針に合わない）。どれも β版では使わない。


## 2. CDK のスタック（`infra/cdk/`）

| スタック | 中身 |
|---|---|
| `Network` | VPC（2つの AZ、公開・プライベート・隔離のサブネット）。本番だけ VPC エンドポイント |
| `Data` | RDS、Secrets Manager、KMS の鍵 |
| `App` | ECR、ECS のクラスター・サービス・タスク定義、ALB、ACM、WAF、ロール（Bedrock は `iam-policy-bedrock.json` と同じ最小の権限） |
| `Dns` | サブドメインのホストゾーン（Route 53）、ACM の証明書、ALB への名前 |
| `Mail` | SES の送信元の確認（DKIM）、送信の設定 |
| `Ops` | 削除の処理（EventBridge）、Budgets、アラーム |

- 環境は `beta`（まず1つ）。本番は同じスタックを別の名前で作る。
- CI では `cdk synth` とスナップショットのテストだけを動かす（AWS には触らない。CI に AWS の認証情報を置かない）。
- **デプロイは、いつもあなたの手元の PC から行う**（2026-11-15 に決定）：`cdk deploy`（構成）と、アプリの入れ替え（イメージを ECR に送ってサービスを更新する）を、`docs/deploy.md` の手順とスクリプト（`pnpm deploy:beta`）で行う。GitHub Actions からのデプロイは作らない。この作業環境（Claude）からも AWS には触らない

## 3. AWS アカウントとドメイン（2026-11-15 に決定）

- **AWS アカウント**：個人のアカウントを使う（すでにあるもの。新しいアカウント向けの無料のクレジットは使えない）
- **ドメイン**：個人で取得しているドメインを使う。**かえりうち用のサブドメイン（例：`kaeriuchi.<個人のドメイン>`）だけを Route 53 に任せる**。いまの DNS に、Route 53 の NS レコード（4行）を足す。ドメイン本体（メールなど）は変えない
- CDK の `Dns` で、サブドメインのホストゾーン、ACM の証明書（DNS で確認）、SES の送信元の確認（DKIM）、ALB への名前を作る。費用は月 約80円
- 個人のアカウントで子どものデータを預かるので、プライバシーポリシーと同意の文の「運営者」は個人になる。「会社としての権利の確認」「同意の文の法律面の確認」のときに、あわせて確かめる

## 4. あなたに用意してもらうもの（AWS の準備のとき）

1. Bedrock の準備（`docs/aws-account-setup.md`、U2 のまま。個人のアカウントで）
2. サブドメインの名前を決め、`cdk deploy` のあと、表示される NS レコード4行をいまの DNS に足す
3. SES の「試しの状態」を外す申請（数日かかることがある）
4. CDK を初めて使うための準備（`cdk bootstrap`。手順は `docs/deploy.md` に書く）
