# 作業ユニット（Units of Work）

Construction フェーズは、次の8つのユニットに分けて進めます（OQ1 でクラウドに同期すると決まったので、U8 を追加しました）。各ユニットは単独でテストでき、PR も1つずつ（大きければ複数）に分けます。

| Unit | 名前 | 含むコンポーネント | 対応するストーリー | 依存先 | 規模 |
|---|---|---|---|---|---|
| U1 | 基盤・プロフィール | C1, C2, C9, C11, `shared/` | US-1.2, US-1.3, US-7.2 | — | M |
| U8 | ログイン・クラウド同期 | C12, C13, S9, S10, `/api/sync`, `/api/account` | US-1.1, US-1.4〜1.6, US-7.3 | U1 | L |
| U2 | AI 基盤（AIProvider・Mock・評価の仕組み） | S1, S2, S6, S7, S8 | （U3 の土台） | U1（`shared/`） | M |
| U3 | 撮影・解析 | C3, C4, `/api/analyze`, S5 の一部 | US-2.1〜2.4, US-3.1〜3.3 | U1, U2, 課題 R1 のスパイク | L |
| U4 | 問題の生成と検証 | S3, S4, S5, `/api/generate` | US-4.1, US-4.6 | U2 | L |
| U5 | バトル・採点 | C5, C6, `/api/grade` | US-4.1〜4.5 | U1, U4 | L |
| U6 | ゲーミフィケーション・再来 | C7, C8 | US-5.1〜5.6, US-6.1〜6.3 | U5 | M |
| U7 | 保護者ダッシュボード | C10, `/api/summarize` | US-7.1 | U6, U8 | S |

## 各ユニットの完了条件

### U1 基盤・プロフィール
- Next.js、TypeScript（strict）、Tailwind、Vitest、Playwright、CI（lint、型チェック、テスト、依存ライブラリと秘密情報のスキャン）が動く。
- プロフィール作成 → プロフィールを選んで始める、までの E2E テストが通る（ログインは U8 で足す。それまでは開発用のログインを使う）。
- IndexedDB のリポジトリ層と、データ構造の移行の仕組み。変更を「送信待ち」として記録する仕組み。
- ホーム画面に追加でき、オフラインでもアプリが開く。
- `output: "standalone"` でビルドでき、`docker compose up` で動く（公開先を固定しない）。

### U8 ログイン・クラウド同期
- `AuthProvider`（開発用と、本番用の実装を1つ）：マジックリンク、パスキーの登録とログイン、端末の一覧とログアウト。
- `SyncStore`（メモリ上で動くものと、Postgres）：push・pull、保護者ごとのデータの境界、書き出し、削除。
- Sync Client：送信待ちの送信、差分の取得、データの種類ごとのまとめ方のルール（`domain-model.md`）。
- 2つの端末で同時に使ったときのシナリオ（XP が両方残る、削除したものが復活しない、オフラインの間の変更が同期される）を自動テストで確認する。
- ほかの保護者のデータには触れられないことを、テストで確認する。
- 本番で使う基盤（ホスティング・保存先・ログイン）を、インフラ設計で比べて決める（OQ7）。

### U2 AI 基盤
- `AIProvider` インターフェース、`MockProvider`、Amazon Bedrock（Claude）のアダプター（OQ5）。
- Route Handler の共通処理（セッションの確認、レート制限、サイズ制限、リクエスト ID、処理時間とトークン数の記録）。
- `evals/` を実行するコマンドと、結果のレポートの形式。

### U3 撮影・解析
- iOS Safari と Android Chrome で、撮影 → 切り抜き → 確認画面まで動く（実機での確認を含む）。
- 送られるのが、切り抜いた画像だけであることを E2E テストで確認する。
- 課題 R1 のスパイクで決めた写り込みへの対策が入っていて、評価用データで目標の値を満たす。
- 信頼度が低い項目の確認を必須にすること、手で入力する方法があること。
- 算数と英語の評価用サンプルで、解析が完全に一致する率が基準以上（基準の値は U2 の最初の測定で決める）。

### U4 問題の生成と検証
- 3種類の問題（同型問題・ポイント問題・確認問題）を作り、検証して、ストリーミングで返す。
- mathjs での検算、選択肢の一意性の確認、検証役 AI での答え合わせ。作り直しと、予備の問題を出す仕組み。
- 生成した問題が検証に合格する率と、検証をすり抜けた誤りの率を、評価で測る。
- 報告を受け取る API と、運用者が報告を判定する簡単な画面。誤りと判定された問題を外す仕組み。

### U5 バトル・採点
- 5種類の答え方（数値、選択、短い文、並べ替え、自己採点）の入力 UI と、ルールでの採点（表記の揺れを吸収する単体テストつき）。
- HP、ヒント、解説、途中からの再開、撤退。
- 撮影 → 撃破まで、MockProvider を使った E2E テストが通る。

### U6 ゲーミフィケーション・再来
- XP、レベル、図鑑、連続記録（お休みチケットつき）、ボスの出現、再来の日程を、純粋な関数として作り、単体テストで網羅する。
- 再来用の問題を前もって作っておき、オフラインで再来バトルができる。

### U7 保護者ダッシュボード
- 教科別・間違いのタイプ別の集計とその推移、TOP5、AI による傾向の要約。
- 保護者向けの画面に入るときの PIN。
- 保護者が自分のスマホでログインして見られる（U8 の同期を使う）。
