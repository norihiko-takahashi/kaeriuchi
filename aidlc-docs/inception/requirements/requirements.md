# 要件定義書 — かえりうち

## 1. 目的・背景

宿題で間違えた問題は、丸付けをしたら終わりになりやすく、同じ間違いを繰り返す原因になります。
「かえりうち」は、**間違えた問題を撮影するだけで、その間違いの原因に合わせた専用の問題（かえりうち問題）が出る**ようにします。
さらに、ゲームの仕組みを使って「間違いを直すこと」そのものを楽しい体験にします。

### コンセプト

- 間違いは「ミスモン（間違いモンスター）」として現れる。撮影すると、ミスモンとのバトルが始まる。
- かえりうち問題に正解すると、ミスモンにダメージを与える。全問正解すれば**返り討ち**（撃破）。
- 倒したミスモンも、忘れかけたころに「再来」する。そこでもう一度倒せば「完全撃破」となり、図鑑に登録される。
- 「間違えた数」ではなく、**倒した数・直した数**をほめる。間違いを隠したくなる気持ちを、間違いを持ってきたくなる気持ちに変える。

### 成功指標（KPI 案）

| 指標 | 目標（ローンチから3か月） |
|---|---|
| 1回撮影したユーザーが、その後2回目も撮影する率 | 60%以上 |
| かえりうち問題を最後まで解いた率（バトル完了率） | 70%以上 |
| 再来ミスモンの撃破率（間違いが定着して直ったかの目安） | 60%以上 |
| AIの解析結果をユーザーが直した率（解析の精度の目安） | 20%以下 |
| 週に3日以上使うユーザーの割合 | 30%以上 |

## 2. 対象ユーザー

| 区分 | 説明 |
|---|---|
| 主ユーザー | 小学1年生〜中学3年生（6〜15歳） |
| 保護者 | アカウントの作成と同意、学習状況の確認、利用ルールの設定を行う |
| 将来の対象（スコープ外） | 塾や学校の先生（クラス単位での管理） |

学年によって、文字の量、ふりがな、操作の複雑さを変えます（小学校低学年、小学校高学年、中学生の3段階）。

## 3. 機能要件

### FR-1 アカウント・プロフィール

- FR-1.0 保護者は、メールのリンク（マジックリンク）でアカウントを作ってログインする。2回目からはパスキー（指紋・顔など）でもログインできる。パスワードは使わない。
- FR-1.1 保護者がアカウントを作り、その下に子どものプロフィールを1〜4人分作れる。
- FR-1.5 保護者が別の端末（保護者のスマホや、子ども用のタブレットなど）でログインすると、同じデータが同期される。
- FR-1.2 子どものプロフィールは、ニックネーム・学年・アバターだけで作れる。本名は不要。
- FR-1.3 子どもは、保護者がログインした端末上で、プロフィールを選ぶだけで使い始められる（PIN は任意）。子ども自身はログインしない。
- FR-1.6 保護者は、ログインしている端末の一覧を見られ、ほかの端末をログアウトさせられる。
- FR-1.4 子どもの学年は年度の切り替えで自動的に上がり、手動でも直せる。

### FR-2 撮影・取り込み

- FR-2.1 PWA からスマホやタブレットのカメラを起動して、宿題を撮影できる。
- FR-2.2 端末に保存済みの写真を選んで取り込むこともできる。
- FR-2.3 撮影した後、**間違えた問題の部分だけを切り抜ける**。名前や学校名など、問題と関係ない部分は送らない。
- FR-2.4 画像は、端末上で縮小・圧縮・向きの補正をしてから送る。
- FR-2.5 1枚の写真に間違いが複数ある場合は、1問ずつ切り抜いて登録できる。
- FR-2.6 教科は選べる。選ばなかった場合は AI が推定する。

### FR-3 AI による間違いの解析

- FR-3.1 切り抜いた画像から、次の内容を読み取る。
  - 問題文
  - 子どもの答え（手書き）
  - 正しい答え（赤ペンの丸付けがあれば、それも手がかりにする）
  - 教科・単元・学年の推定
  - **間違いのタイプ**（例：繰り上がりのミス、符号のミス、漢字のとめ・はね、三単現の s が抜けている、用語の取り違え、問題文の読み違い、など）
  - 推定の確からしさ（信頼度）
- FR-3.2 解析結果は確認画面に出し、子どもや保護者が直せる。信頼度が低いときは、確認を必須にする。
- FR-3.3 読み取れなかったときは、撮り直すか、問題と答えを手で入力するかを選べる。
- FR-3.4 解析結果は「ミスモン」として保存する。間違いのタイプによって、ミスモンの種族が決まる。

### FR-4 かえりうち問題（専用問題）の生成

- FR-4.1 解析した間違いのタイプに合わせて、**類題を3〜5問作る**。構成は次のとおり。
  1. 同じ型で数字や語句を変えた問題（同型問題）
  2. 間違えたポイントだけを取り出した問題（ポイント問題）
  3. 少しだけ発展させた問題（確認問題）
- FR-4.2 答え方の形式は、教科や問題に合わせて選ぶ。
  - 数値入力・式入力（算数・数学・理科の計算）
  - 選択式（全教科）
  - 短い文の入力（英語、社会・理科の用語）
  - 並べ替え（英語の語順、国語の文の組み立て）
  - 漢字：読みを答える問題、選択式、手書きの自己採点（お手本と見比べる）
- FR-4.3 各問題には、ヒント（段階的に2つまで）と解説をつける。
- FR-4.4 生成した問題は、**出す前に正しさを検証する**（§5.3）。
- FR-4.5 問題の言葉づかい、ふりがな、数の大きさは学年に合わせる。

### FR-5 バトル（出題・採点）

- FR-5.1 ミスモンとのバトル画面で、かえりうち問題を1問ずつ出す。
- FR-5.2 正解するとミスモンにダメージ。間違えたらヒントを出して、もう一度挑戦できる。
- FR-5.3 採点の方法
  - 数値・選択・並べ替え：端末上で決まったルールどおりに採点する（表記の揺れも吸収する。例：全角と半角、`1/2` と `0.5`）。
  - 短い文：同じ意味の答えの一覧で採点し、一覧で判断できなければ AI に採点させる。
  - 手書きの自己採点：お手本を見せ、子どもが「できた／もう一回」を選ぶ。
- FR-5.4 バトルの結果は「撃破」「あと一歩」「撤退」のどれか。撤退してもペナルティはない。
- FR-5.5 途中でやめても、次は続きから再開できる。

### FR-6 ゲーミフィケーション

- FR-6.1 **XP とレベル**：撃破、ヒントを使わずに正解、再来の撃破などで XP がもらえる。
- FR-6.2 **ミスモン図鑑**：間違いのタイプごとに種族があり、撃破すると登録される。完全撃破すると図鑑のカードが「金色」になる。
- FR-6.3 **連続記録（ストリーク）**：1日1バトルで続く。週に1回は「お休みチケット」で途切れない。
- FR-6.4 **ボス戦**：同じ単元のミスモンが一定数たまると、その単元のボスが現れる。複数の種類の問題が混ざった総合問題で戦う。
- FR-6.5 **コイン・きせかえ**：コインでアバターの見た目を変えられる。**課金とは連動させない**。
- FR-6.6 **ほめる演出**：撃破したとき、間違いを持ってきたときに、ほめる言葉と演出を出す。
- FR-6.7 他人とランキングで比べる仕組みは入れない。比べるのは過去の自分とだけ。

### FR-7 復習スケジュール（ミスモンの再来）

- FR-7.1 撃破したミスモンは、間をあけて繰り返す方式で再来させる（初期値：1日後、3日後、7日後、14日後、30日後）。
- FR-7.2 再来のときは、新しい類題を作る（同じ問題を覚えて答えるだけにさせない）。
- FR-7.3 再来でまた間違えたら、間隔を最初に戻す。
- FR-7.4 ホーム画面に「今日の再来ミスモン」を表示する。

### FR-8 保護者ダッシュボード

- FR-8.0 保護者は、自分のスマホでログインしてダッシュボードを見られる（クラウド同期のデータを使う）。
- FR-8.1 教科・単元・間違いのタイプ別に、間違いと撃破の件数の推移を見られる。
- FR-8.2 「よくある間違い TOP5」と、その傾向の説明（AI が作った要約）を見られる。
- FR-8.3 1日の撮影回数の上限、使える時間帯、通知の有無を設定できる。
- FR-8.4 子どものデータを書き出したり、削除したりできる。削除すると、クラウドに保存したデータも削除される（バックアップからも、決めた期間内に消す）。
- FR-8.5 アカウントを削除できる。削除すると、保護者と子どものデータがすべて削除される。

### FR-9 同期

- FR-9.1 データは端末内（IndexedDB）にも持ち、オフラインでもバトルや再来ができる。オンラインに戻ったら、クラウドと同期する。
- FR-9.2 同じデータを複数の端末で変更したときは、データの種類ごとに決めたルールで1つにまとめる（例：XP やコインは加算、プロフィールは最後に更新したものを採用、バトルの記録は追記だけ）。
- FR-9.3 サムネイル画像は端末内だけに保存し、クラウドには送らない（保護者が「画像も同期する」をオンにしたときを除く）。

## 4. 対象外（今回のスコープに含めないもの）

- 先生・塾向けの機能（クラス管理、課題の配布）
- 宿題全体の自動丸付け（このアプリは「間違えた問題」から始める前提）
- ユーザー同士の交流、ランキング、チャット
- 課金・アプリ内課金（収益の方式はまだ決めない。OQ3）
- 手書きの漢字を AI で採点する機能（OQ4）
- ネイティブアプリ（iOS / Android）。まずは PWA で出す。
- 作文や記述式の長い答えの添削

## 5. 非機能要件

### 5.1 プライバシー・子どもの保護（最優先）

- NFR-P1 個人情報保護法に従う。子ども（16歳未満を想定）の利用は**保護者の同意**を前提にする。海外の基準（米国の COPPA、欧州の GDPR-K）にも将来合わせられる設計にする。
- NFR-P2 画像は**切り抜いた部分だけ**を送る。AI の解析に使った画像は、サーバーに**保存しない**（解析が終わったらメモリから消す。デバッグ用に残す場合も、保護者の同意を得て、最長30日）。
- NFR-P3 AI プロバイダーには「学習に使わない」設定（データを学習に使わない契約）で送る。
- NFR-P4 子どもの本名、学校名、顔などが画像に写っていたら、警告を出す（端末上での簡単な検知と、AI 解析時の検知）。
- NFR-P5 AI が作る文章には、子ども向けとして不適切な内容がないかのフィルターをかける。
- NFR-P6 クラウドに保存するのは、学習に必要な最小限のデータだけにする（ニックネーム、学年、ミスモンの文字の情報、成績、ゲームの状態）。本名、学校名、画像は保存しない（FR-9.3）。
- NFR-P7 データは国内のリージョンに保存し、通信時も保存時も暗号化する。データには保護者ごとの境界（テナントの分離）を設け、ほかの保護者のデータには、仕組みのうえで触れられないようにする。
- NFR-P8 運用者がデータを見るときは、ログを残す。退会した保護者のデータは、30日以内にバックアップも含めて削除する。

### 5.2 性能

- NFR-S1 撮影してから確認画面が出るまで、p90 で8秒以内。待っている間はミスモンが現れる演出を見せる。
- NFR-S2 かえりうち問題の生成は、p90 で10秒以内。1問目が届いたらすぐ出し、残りは後から届いてもよい（ストリーミング、または段階的に出す）。
- NFR-S3 バトル中の採点は、端末上で採点するもので100ms以内。
- NFR-S4 一度解析したミスモンとの再戦は、オフラインでもできる（再来用の問題は前もって作っておく）。

### 5.3 AI の品質

- NFR-Q1 生成した問題の**正答を検証する**。
  - 算数・数学：数式を計算するエンジンで機械的に検算する。
  - 選択式：正解が1つだけで、ほかの選択肢が正解になっていないことを確認する。
  - それ以外：別の呼び出し（検証役の AI）で答え合わせをし、食い違ったら作り直すか、その問題を外す。
- NFR-Q2 AI の出力は**決められた形式（JSON スキーマ）**で受け取り、形式チェックに失敗したら再試行する（最大2回）。
- NFR-Q3 「問題がおかしい」と報告するボタンをつけ、報告されたものはプロンプトの改善に使う。
- NFR-Q4 プロンプトと評価用データ（教科・学年ごとに 50 件以上の正解つきサンプル）をリポジトリで管理し、プロバイダーやモデルを変えたときは、まとめて評価をやり直す。

### 5.4 AI プロバイダーの非依存

- NFR-A1 AI は `AIProvider` インターフェースの後ろに隠し、Claude API、Amazon Bedrock、ほかの LLM、モックを設定で切り替えられるようにする。
- NFR-A2 開発とテストでは**モックのプロバイダー**（決まった答えを返すもの）で、全機能が動くこと。
- NFR-A3 API キーや認証情報はサーバー側（Next.js の Route Handler）だけで持ち、端末には渡さない。
- NFR-A4 最初に検証する AI は **Claude（Amazon Bedrock）**。評価の結果によって、ほかのプロバイダーに変えてよい（OQ5）。

### 5.4b 基盤の非依存（OQ7）

- NFR-I1 公開先（ホスティング）は固定しない。Next.js を、特定のクラウドだけの機能に頼らずに動かせるようにする（Docker でも Vercel でも Amplify でも動く）。
- NFR-I2 同期の保存先（`SyncStore`）とログインの基盤（`AuthProvider`）は、インターフェースの後ろに隠す。開発とテストでは、端末内で動くもの（ローカルの Postgres、またはメモリ上で動くもの）で全機能が動くようにする。
- NFR-I3 どの基盤を使うかは、U1 と U8 のインフラ設計で比べて決める（候補は open-questions の OQ7 の補足）。

### 5.5 コスト

- NFR-C1 1ユーザーあたり、1日の撮影回数に上限を設ける（初期値10回。保護者が設定を変えられる）。
- NFR-C2 1回の撮影（解析＋生成＋検証）にかかる AI のコストの上限を決め、計測する。
- NFR-C3 再来用の問題は、使われていない時間帯に前もって作っておき、作った結果は再利用する。

### 5.6 使いやすさ・アクセシビリティ

- NFR-U1 小学校低学年向けモード：ふりがなつき、音声で読み上げる、ボタンを大きくする、文字を少なくする。
- NFR-U2 WCAG 2.2 AA に準拠する（色のコントラスト、キーボード操作、スクリーンリーダー対応）。
- NFR-U3 タブレットを縦にも横にも置ける。片手で撮影できる。
- NFR-U4 演出（アニメーション）は、OS の「視差効果を減らす」設定に従う。

### 5.7 対応環境

- NFR-E1 iOS Safari 17 以上、Android Chrome の最新2バージョン、iPadOS を対象にする。
- NFR-E2 ホーム画面に追加できる PWA。Service Worker で、アプリ本体とバトル用のデータをオフラインでも使えるようにする。

### 5.8 セキュリティ

- NFR-X1 サーバーの API には認証、レート制限、入力サイズの上限（画像は 2MB）を設ける。
- NFR-X2 プロンプトインジェクション対策：画像の中の文字は「データ」として扱い、指示としては実行させない。出力は JSON スキーマでしか受け付けない。
- NFR-X3 依存ライブラリの脆弱性スキャンと、秘密情報のスキャンを CI で行う。

## 6. 前提・仮定

確認の質問で答えをもらっていない点は、次のように仮定して進めました。違っていれば教えてください。

| # | 仮定 | 理由 |
|---|---|---|
| A1 | 撮影するのは「すでに丸付けしてある宿題」 | 赤ペンの丸付けを手がかりにすると、正しい答えと間違いの部分を特定する精度が上がる。丸付けしていない場合でも、AI の推定で動くようにはする |
| A2 | 端末は保護者が管理するもの、または子ども専用のスマホ・タブレット | 子ども自身のメールアドレスでのログインは求めない |
| A3 | ~~MVP ではデータを端末内だけに保存する~~ → OQ1 で**クラウドに同期する**と決まった | — |
| A4 | 教科書の出版社ごとの単元の並びは使わず、学習指導要領のおおまかな単元で分ける | 出版社ごとの対応表は作るのが大変なので、後から足す |
| A5 | 表示は日本語。英語は「教科」として扱う | 対象が日本の小中学生のため |
| A6 | MVP は無料。撮影回数の上限は設定で変えられるようにする | 収益の方式はまだ決めない（OQ3） |
