# 未決事項（回答済み）

2026-11-08 に、チャットで1問ずつ回答をもらいました。

| # | 論点 | 決定 | 設計への影響 |
|---|---|---|---|
| OQ1 | データの保存先 | **最初からクラウドに同期する** | 保護者が自分のスマホで見られる。サーバーが子どものデータを持つので、プライバシーの要件を強める（NFR-P2〜P8）。端末内の IndexedDB は、オフライン用のキャッシュとして使う |
| OQ2 | ログインの方式 | **メールのリンク（マジックリンク）＋パスキー** | ログインするのは保護者だけ。子どもは、保護者がログインした端末でプロフィールを選ぶ |
| OQ3 | 収益の方式 | **まだ決めない** | MVP は無料。撮影回数の上限は設定で変えられるようにする。課金の仕組みは作らない |
| OQ4 | 漢字の書き取り | **読みを答える問題・選択式・手書きの自己採点** | AI で手書きを採点する機能は、MVP より後に検討する |
| OQ5 | 最初に検証する AI | **Claude（Amazon Bedrock）**。ただし固定はしない | Bedrock のアダプターを最初に作り、評価用データでの検証もこれから始める。評価の結果によっては、ほかのプロバイダーに変えてよい |
| OQ6 | キャラクター・世界観 | **仮の SVG で作り、後から差し替える** | 種族の定義（データ）と絵（アセット）を分けておく |
| OQ7 | 公開先・同期の保存先・ログインの基盤 | **固定しない** | `SyncStore` と `AuthProvider` も、`AIProvider` と同じように差し替えられる形にする。特定のクラウドだけの機能に依存しない。どれを使うかは、U1 と U8 のインフラ設計で比べて決める |

## OQ7 の補足（インフラ設計で比べる候補）

| 構成 | 長所 | 気になる点 |
|---|---|---|
| AWS（Amplify Hosting、または ECS／App Runner ＋ Cognito ＋ DynamoDB） | Bedrock と同じアカウントにまとめられる。東京リージョンにデータを置ける | 構成が複雑になりやすい |
| Vercel ＋ Supabase（Postgres ＋ Auth） | 開発が速い。パスキーに対応している | Bedrock を呼ぶための AWS の認証情報を、外部に置くことになる |
| コンテナ（Docker）＋ マネージドの Postgres ＋ Auth.js | 一番移しやすい | 運用を自分たちでやる部分が増える |
