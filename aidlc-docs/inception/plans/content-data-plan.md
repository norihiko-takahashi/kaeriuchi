# コンテンツとデータの作成計画

2026-11-08 に、推奨案で決定しました。

## A. 間違いのタイプの一覧（ミスモンの種族のもとになる分類）

**方針：A1（公開資料）＋ A2（AI の下書きを人が見直す）＋ A3（使われながら育てる）**

| 段階 | やること | 対象 | 置き場所 |
|---|---|---|---|
| 1. 土台 | 全国学力・学習状況調査の報告書（国立教育政策研究所が公開している、問題ごとの誤答の類型）と、学習指導要領の解説から、間違いのタイプを抜き出す | 算数・数学、国語（英語・理科も、調査がある年の分は使う） | `content/mistake-types/*.yaml` |
| 2. 補完 | 単元の一覧を AI に渡して、よくある間違いの候補を出させ、教育に詳しい人が見直して承認する | 1 で足りない教科・学年 | 同上（`source: ai-draft` と、見直した人を記録する） |
| 3. 育成 | 解析で当てはまらないものは `other` と自由な説明で記録する。定期的に AI で似たものをまとめ、件数が多いものを人が承認して、新しいタイプにする | 全教科 | 承認したら YAML に追加する（PR でレビューする） |

### 一覧の形式（案）

```yaml
- id: math.fraction.add-denominators
  subject: math
  unit: 分数のたし算
  grades: [e5]
  label: 分母どうしも足してしまう
  example: { question: "1/2 + 1/3", wrong: "2/5", correct: "5/6" }
  species: bunbo-gattai        # ミスモンの種族
  source: nier-2023            # nier-<年> / curriculum / ai-draft / usage
  reviewedBy: "<見直した人>"
```

### 決めること（Construction で）
- ~~段階 2 で見直す人を誰にするか~~ → **まずユーザーが見直し、β版の前に元教員などにも見てもらう**（2026-11-12 に決定）。見直した人と日付は、各タイプの `reviewedBy`・`reviewedOn` に入れる。
- 段階 3 で、どのくらいの件数になったら新しいタイプにするか。

### いまの状態（2026-11-12）
- 下書き 80種類（算数・数学 31、国語 14、英語 14、理科 10、社会 11）。`source: ai-draft`。全国学力・学習状況調査の報告書（段階 1）とは、まだ照らし合わせていない。
- 形式は YAML ではなく、教科ごとの JSON（`content/mistake-types/<教科>.json`）にした。YAML を読むライブラリを足さずに、サーバーでも画面でもそのまま読めるため。項目は上の案と同じ（`species` の代わりに、仮のミスモンの `monster` と `color`）。
- 画面には、名前・ミスモン・色・教科・学年だけの小さい一覧（`screen.json`、`scripts/mistake-types-screen.mjs` で作る）を使う。例まで画面に入れると、JavaScript の大きさの予算を超えそうになるため。
- AI に渡す候補は、教科と、子どもの学年の前後1学年のものに絞る。AI が候補の外の（一覧にはある）タイプを返したときは、そのまま受け付ける。

## B. 評価用データ（正解を付けた宿題の写真）

**方針：B1（自分たちで書く）＋ B2（合成する）から始め、β版で B3（協力家庭）を少量、運用後は B4（本番の修正から学ぶ）を続ける**

| 段階 | 時期 | やること | 量の目安 |
|---|---|---|---|
| B1 自分たちで書く | U2〜U3 | チームのメンバーや協力者が、プリントにわざと間違えた答えを手書きし、赤ペンで丸付けをして撮る。丸付けしたものとしていないもの（課題 R2）、実在しない名前が写ったもの（課題 R1）、問題文に登場人物の名前があるものを、わざと入れる | 教科ごとに 30 件以上 |
| B2 合成する | U2〜U3 | 問題の文字・手書き風のフォント・赤ペンの丸を、プログラムで組み合わせて画像を作る。照明、傾き、紙のしわもわざと付ける。正解は自動で付く | 教科・学年ごとに 50 件以上 |
| B3 協力家庭 | β版 | 別の同意を取ったうえで、協力家庭から写真を提供してもらう（下記の条件つき） | 少量（本物の写真との差を測るのに足りる量） |
| B4 本番の修正 | 運用後 | 確認画面で直された内容を、文字の情報だけで記録する。修正の率を、教科・単元・プロンプトの版ごとに見る | 自動で集まる |

### B3 を始める条件
- 課題 R1（写り込みへの対策）が決まっていること。
- 通常の同意とは別に、「評価に使う写真の提供」の同意を取る画面と手順があること（何に使うか、いつ削除するか、いつでも取り下げられること）。
- 提供された写真は、評価用の場所にだけ置き、アクセスできる人を限り、決めた期間が過ぎたら削除すること。
- `data-inventory.md` に、例外として追加してレビューを受けること。

### 評価用データの置き場所
- B1・B2 は、リポジトリの `evals/`（容量が大きければ、外部のストレージに置いて、場所だけを記録する）。
- B3 は、リポジトリに入れない。アクセスを限った専用の場所に置く。
