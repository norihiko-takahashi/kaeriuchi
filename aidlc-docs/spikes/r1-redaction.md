# R1 スパイク：本名・学校名などが写った写真への対策

課題 R1（`inception/requirements/open-questions.md`、Issue #1）の検証の記録です。U3（撮影・解析）を始める前に、方法と目標の値を決めます。

## 1. いまの段階（2026-11-12）

AWS の準備がまだなので、**端末だけでできる方法**と、**読み取った文字への規則**から試しました。本物の写真はユーザーが用意します（市販のドリルなどに、実在しない名前を書いて丸付けしたもの）。

| 方法 | 状態 |
|---|---|
| 赤ペンの印を見つけて、枠の候補を出す（名前の欄は枠の外になる） | 試作し、見本の画像で測った（§2） |
| 読み取った文字への規則（名前の欄・学校名・クラス・先生・連絡先） | 試作し、見本の文で測った（§3） |
| かくすペン（指でなぞって塗りつぶす） | 赤ペン検知ラボに試作を入れた（§6）。塗ったところが、送る切り抜きから消えることを確かめた。子どもに試してもらうのはこれから |
| AI に個人情報の種類と場所を返させる | AWS の準備のあと |
| 端末での文字認識（OCR） | 試していない。手書きの日本語の精度と、読み込むデータの大きさ（子ども向けの画面の予算は 200KB）が合わない見込み |
| 顔の検知 | 試していない。宿題に顔が写ることは少なく、検知の仕組みを読み込む重さに見合うかを、本物の写真で確かめてから決める |

## 2. 赤ペンの印の検知（`spikes/r1/redmarks.ts`）

- ブラウザの中だけで動く（Canvas の画素を読む）。写真は端末の外に出さない。
- 紙の白さで色と明るさをそろえ、鮮やかな赤だけを選び、形で ○ と ✗・✓・／ を分ける。赤で印刷された文字（横に並んだもの）は捨てる。
- 間違いの印のまわりに、問題1問分の枠の候補を出す。

**見本の画像（12種類の条件 × 5枚、1枚 8問）での結果**（`pnpm spike:r1`）

| 項目 | 結果 |
|---|---|
| 間違いの印（✗・✓・／）を見つけられた率 | 100%（360/360） |
| ○ を間違いの印と取り違えた率 | 0%（0/120） |
| 印でないもの（赤い見出し、ピンクの蛍光ペン）を印とした数 | 0 |
| 枠が名前の欄の 20% 以上を含んだ数 | 0 |
| 速さ（Node、1200×1600） | 平均 約150ms（暗い写真で 約350ms） |

途中で直したこと：最初は、かすれた赤ペンを 0% しか見つけられず、細い赤ペンの ○ の 70% を間違いの印と取り違えた。赤とみなすしきい値を下げ、縮める大きさを 640px から 960px にした。

**枠の大きさで見つかったこと（2026-11-12、ラボで切り抜きを並べて見て）**
- 印が**答えの上**に付いていると、枠が答えのまわりだけになり、**問題文が入らない**。いまの枠は「印の大きさ × 決まった倍率」で、問題の行の幅を見ていないため。
- 問題番号の上に付いた印では、問題文が入る。
- U3 では、枠を「印のある行の、左の端（問題番号）まで」広げる。行は、印刷の黒い文字の並びから見つける。子どもが枠を広げられるのは変わらない（US-2.3）。

**この結果をそのまま信じてはいけない理由**
- 見本の画像は、私が描いたもの。描き方と見つけ方を同じ人が作っているので、本物の写真より簡単になっている。
- 本物の手書きの ○ は、もっと形が崩れる。✓ と ○ の中間のような印もある。
- 速さは Node で測った。古いスマホのブラウザでは、何倍か遅くなる見込み。

### 本物の写真 1枚目（2026-11-12、ユーザーが撮った漢字検定のドリル。縦書き）

写真はリポジトリに入れない（ユーザーの指示。市販のドリルのページでもある）。わかったことだけを書く。

| 項目 | 写真の中 | 仕組みの結果 |
|---|---|---|
| ○ | 約20 | 色を直す前：0。直したあと：○ と判定できたのは 1（ほかは切れた弧として「間違い」に混ざった） |
| 間違い（問題番号の四角に「／」、△、✗） | 約10問 | 色を直したあと：印は拾えるが、直しの字・切れた ○ を含めて 37 になった |
| 枠 | 縦の1列が1問 | 横長の枠になり、合わない |
| 速さ | 1932×2576 | 約 0.44秒（パソコンの Chromium） |

わかったこと：
1. **ペンがマゼンタ（色相 330〜345°）**だった。鮮やかさは 0.33 ほど（暗めの部屋）。赤だけを見るしきい値では、細い線を全部落としていた → 色相で見るように直した（見本の画像の結果は変わらない）。
2. **○ が手書きの字にかかって描かれ、つながった輪にならない**。形で ○ を見分けるやり方は、ほぼ効かない。
3. 間違いの印は、**問題番号の四角に引く「／」**だった。答えの上とは限らない。
4. **縦書き**。枠は「印の行」ではなく、問題から答えの欄までの「列」で考える必要がある。
5. 間違えた問題には、**正しい答えがピンクで書き込まれる**。これも「間違い」の手がかりになる。

見立て：形の決まりだけで印と枠を決めるやり方は、テストごとの書き方の違い（縦・横、印の付け方）に弱い。**ピンクの部分だけを抜き出した画像**（鉛筆の名前は写らない）を AI に渡して、どこが間違いかを判断させる方法（計画の「逃げ道」）の方が見込みがある。写真がもう何枚かそろってから決める。

### 本物の写真 2〜4枚目（2026-11-12。数学の文章題のプリント 2枚、漢字のドリル 1枚）

写真はリポジトリに入れない。

| 写真 | 仕組みの結果 | 起きていたこと |
|---|---|---|
| 数学 1（横書き） | 「間違い」56、○ 1 | **子どもが式と答えを赤ペンで書いている**。それを全部拾った |
| 数学 2（横書き） | 「間違い」49、○ 0 | 同じ |
| 漢字（縦書き、横向きに撮影） | 「間違い」76、○ 1 | **答えが全部赤ペン**。先生の ○ は 1つだけ |

わかったこと：
1. **子どもが自分で赤ペンを使う**（式・答え・直し）。「赤ペン＝先生の丸付け」という前提が成り立たない。
2. 写真が**横向き**のことがある（向きを直す処理が要る）。
3. 答えの下線の端の小さな「＼」が、先生の印か子どもの書いたものか、**人が見ても判断がつかない**ことがある。
4. 名前の欄はページの上（「1年 組 番 氏名」）。この2枚は空欄だった。

**結論（4枚を見て）**：赤い色から先生の丸付けを自動で読むやり方は、調整で直る問題ではないので、やめる。「赤・ピンクの部分だけを AI に渡す」逃げ道も、子どもが赤で書くと名前以外の手がかりが崩れるので、使わない。U3 の枠は、**子どもが指で囲む**（自動の候補は出さない）に決めた（2026-11-12、ユーザーの判断）。

## 決めた方法（2026-11-12）
1. 子どもが間違えた問題を指で囲む。囲んだ枠の中だけを送る（名前の欄は、ふつう枠の外になる）
2. 送る前の確認で「かくすペン」が使える
3. サーバーで、読み取った文字に規則（§3）と AI の判定をかけ、見つかったら伏せ字にして進める
4. 目標の値は、AWS の準備のあと、本物の写真を読み取った文字で測ってから決める（Issue #1 はそこまで開けておく）

`spikes/r1/redmarks.ts` と検知ラボは、検証の記録として残す（アプリには使わない）。かくすペンと、文字への規則（`pii-text.ts`）は U3 で使う。

## 3. 読み取った文字への規則（`spikes/r1/pii-text.ts`）

- 「なまえ／名前／氏名」のあとに何か書いてあるもの、〇〇小学校、〇年〇組、〇〇先生、電話番号・メール・郵便番号を見つける。
- 「名前を 書きましょう」「先生が 黒板に…」「たろうくんは…」のような問題の文は止めない。

**見本の文（止めるべき 18、止めてはいけない 21）での結果**：止めるべき文を 100% 見つけ、止めてはいけない文は 0% 止めた。

途中で直したこと：ひらがなの学校名（ひかり小学校）を見逃し、「名前を 書きましょう」を止めていた。

**この結果をそのまま信じてはいけない理由**：見本の文も私が書いたもの。本物は、AI が手書きを読み間違えた文になる（「3年2組」が「3年2紐」になる、など）。

## 4. いまの見立て（本物の写真で確かめる前）

守りを3つ重ねる案です。

1. **切り抜く（いちばん効く）**：赤ペンの印のまわりだけを枠の候補にする。名前の欄には印がないので、ふつうは最初から枠の外になる。子どもが枠を広げて名前の欄を含めたときだけ、次の守りに頼る。
2. **かくすペン**：送る前の確認の画面で、名前などを指でなぞって消せる。
3. **読み取った文字の確認（サーバー）**：AI が読み取った文字に、規則と AI の判定をかける。見つかったら、**その文字を「〇〇」に伏せて進める**（2026-11-12 に決定）。確認の画面で「なまえが うつっていたかも。つぎは かくすペンで けしてね」と知らせる。伏せる前の文字は、端末にもクラウドにも残さない。

## 6. 赤ペン検知ラボ（写真を送らずに測る）

- スマホで開いて写真を選ぶと、見つけた印（赤い四角＝間違いの印、緑の丸＝○）と、切り抜く枠の候補（青い点線）を重ね、1枚ごとの処理の時間を出す。
- 写真ごとに、ユーザーが数えた正しい数を入れると、見つけられた率などを出す。結果の文をコピーして、チャットに貼る。
- 検知は Web Worker の中で行う。写真はその端末の中だけで処理し、どこにも送らない。**写真をリポジトリに入れなくても測れる**。
- **かくすペン**：写真の上を指でなぞると黒く塗れる。「送る部分を見る」で、AI に送ることになる切り抜きを並べ、塗ったところが消えているのを確かめられる。何枚で使ったか、なぞった回数、かかった時間も結果に出る。

## 7. 写真の用意の仕方（ユーザーへのお願い）

- 市販のドリルや、印刷したプリントを使う（家族の本物の宿題は使わない）。
- 名前の欄には、**実在しない名前**を書く（例：「ほしの そら」）。学校名・クラスの欄があれば、それも架空のものにする。
- 答えを鉛筆で書き、赤ペンで ○・✗・✓・／ を混ぜて丸付けする。
- 撮り方を混ぜる：明るい部屋、暗めの部屋、暖色の照明、手やスマホの影が入る、少し斜め、再生紙（黄ばんだ紙）、細い赤ペン、かすれた赤ペン、赤い見出しのあるプリント。
- **顔や家の中が写らないように**撮る。
- **位置情報を消す**：iPhone は共有のときに「オプション」で位置情報をオフ、Android はカメラの設定で位置情報をオフにしてから撮る。
- **写真はリポジトリに入れない**（2026-11-12、ユーザーの指示）。チャットで送ってもらい、作業用の場所でだけ使う。わかったことは文章で記録する。
